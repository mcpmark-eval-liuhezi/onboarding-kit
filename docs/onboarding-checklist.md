# First-Weeks Onboarding Checklist

A concrete checklist for new engineers joining the team. Work through it top to bottom, and tick items off as you go. If anything is blocked, raise it in the team channel or with your onboarding buddy.

## Day 1

- [ ] Verify your GitHub account and enable two-factor authentication
- [ ] Confirm access to the team's repositories, GitHub organization, and relevant teams
- [ ] Set up your accounts and access: email, chat (Slack/Teams), calendar, video conferencing
- [ ] Install core tooling: package manager, git, editor/IDE, terminal, and any required SDKs
- [ ] Clone the main repository and confirm you can run the test suite locally
- [ ] Meet your onboarding buddy and your manager for a welcome chat
- [ ] Read the team README and this checklist end to end

## First week

- [ ] Finish tooling setup: linters, formatters, pre-commit hooks, and local environment configuration
- [ ] Get access to CI/CD pipelines, logging, monitoring, and the deployment dashboards you'll need
- [ ] Pair with a teammate on a small task or bug fix to learn the workflow
- [ ] Open your first pull request and go through your first code review
- [ ] Attend team stand-ups, sprint planning, and any recurring team ceremonies
- [ ] Meet the team: schedule short intro chats with each teammate and key stakeholders
- [ ] Skim the architecture overview and on-call runbook to get oriented

## First month

- [ ] Ship a small feature or meaningful change end to end (code, review, deploy)
- [ ] Review someone else's pull request for the first time
- [ ] Complete required training: security, compliance, and any domain-specific modules
- [ ] Join a deeper dive: shadow an on-call rotation or participate in a design review
- [ ] Write or improve one piece of documentation you found confusing as a newcomer
- [ ] Give structured feedback on this onboarding checklist to your buddy and manager
- [ ] Agree on 30-day goals with your manager and set up a check-in cadence
